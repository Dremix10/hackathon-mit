## 2026-10-04 (driver failures are not actions)

The first live pilot sent `temperature` to `claude-sonnet-5`. That model returns HTTP 400 (`temperature is deprecated for this model`). `CoopSim.play` recorded each failure as `action_rejected` and still wrote `meta.status = complete`, so a batch can look finished with zero real model calls. The Red-Teamer owns the fail-loud check in `coop/batch` and dropping sampling params in `coop/agents/llm.py`. This entry is the simulator side. Do not treat a `driver_failure` run as confirmatory.

- `driver_error` is a new event type (channel `system`). Payload: `actor`, `error_class`, `status_code`, `message`, `attempt`. It is an API or driver failure (HTTP error, timeout, auth, or a response that is not a model completion). `action_rejected` is only a real model response that is an invalid or impermissible action. `coop.schema.EVENT_TYPES` and `coop.eval.contract.SIM_EVENT_TYPES` both include `driver_error`.
- Outcome code ignores those turns. `coop.eval.outcomes` drops them before Y, T*, T**, and the persistence checks. `coop.analysis` drops them in the primary Y helper, the leader rules, hypothesis scores, and the blind classifier input. A `driver_error` is not a violation and is not Y.
- Transient errors (429, 408, 5xx, timeouts, connection `URLError`) retry up to 3 attempts with backoff 0.5s, 1s, 2s. 400 and 401 are not retried. A 400 whose message says temperature, top_p, or top_k is deprecated is recorded on the process and retried once with those fields omitted.
- A non-retryable driver error ends the run immediately. So does an agent with driver errors and zero successful `llm_call`s, or an agent whose errored-turn share is above `max_driver_error_rate` (default 0.10). `meta.status` is `driver_failure` and `abort_reason` is set. It is never `complete`. `error` remains the status for an unexpected exception outside the driver. Before round 1, a policy with `preflight()` gets one tiny call; if that raises `DriverError`, the run aborts with `driver_failure` and no events.
- `coop/sim/llm.py` keeps `OMIT_SAMPLING_MODELS`. `claude-sonnet-5` (and any model that matches the deprecation error) does not send `temperature`, `top_p`, or `top_k`. `meta.agents[].temperature` is the value actually sent, so it is null when omitted, and those agents gain `sampling: "model_default"`. Mock and scripted agents do not get that field. `config_sha256`'s `temperature` input is that sent value, not the requested one. Two temperatures on `claude-sonnet-5` hash the same. `sim_git_sha` is still outside the hash.
- `research/seed_log.jsonl` rows now include `status`. `driver_failure` and `error` do not count as a held-out replication. With `--redraw-failed` (the default on `coop.sim.run` and `coop.sim.batch`) those rows are excluded from the used-seed set, so the same seed can be drawn again. `--no-redraw-failed` burns them. Older log lines with no status stay used. `aborted_budget` stays used.
